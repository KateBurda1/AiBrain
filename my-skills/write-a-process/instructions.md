# Write a Process

## Goal
Turn a verbal explanation, messy notes, or "the way we do things" into a clean, step-by-step document that anyone on the team can follow without asking questions.

## Inputs
- What process do you want documented? (how you onboard a client, how you close up the shop, how you handle a refund, etc.)
- Talk through it naturally. Just explain how you do it, step by step. Do not worry about being organised. That is what this skill does.

## Steps

### Step 1: Listen and capture
Let the user explain the process in their own words. Ask follow-up questions if steps are unclear or seem to be missing. Common gaps:
- "What happens before that?"
- "Who does that step?"
- "What if something goes wrong at that point?"
- "How do you know when this step is done?"

### Step 2: Organise into steps
Structure it as:

**Process name:** [clear title]

**Purpose:** One sentence on why this process exists.

**Who does it:** [role or person]

**When:** [when this process runs - daily, when a new client signs, etc.]

**Steps:**
1. [Clear action with enough detail to follow]
2. [Next step]
3. [Next step]
...

**If something goes wrong:**
- [Common issue] → [What to do]

**Checklist version:**
- [ ] [Step 1]
- [ ] [Step 2]
- [ ] [Step 3]
...

### Step 3: Review with the user
Show the process and ask: "Does this cover everything? Any steps missing? Anything in the wrong order?"

Revise based on feedback.

## Output format
Display the process in the conversation. If approved, save to `my-work (outputs)/internal/` or the relevant client folder.

## Quality check
- Could a new team member follow this without asking questions?
- Every step is a clear action, not vague ("Process the order" is vague, "Open the POS, scan the item, confirm payment method" is clear)
- Common failure points are covered
- Checklist version is included for quick reference
