# Wylie Inn — Weekly Revenue Report Automation Spec

**Status:** v1 built. The script can build a full report (STR, Lighthouse,
Booking.com, Synxis, Expedia Promotions + screenshots), but **Kate's actual
weekly routine going forward is Lighthouse + Synxis only** — that's the
rate-shop-vs-availability join that drives the real call decision, and the
most reliable of the sources. The rest of the script stays available if she
wants a fuller build some week, but isn't the default.
**Owner:** Shelby (build), Kate (source access)
**Goal:** Cut down the manual screenshot/read/type work in the weekly Wylie Inn revenue management report, without needing connectors that don't exist for these platforms.

## Current process

Every week, Kate logs into five separate platforms, reads or screenshots competitive
and performance data by hand, and assembles it into a Word doc
(`Kate & Co/Client Files/Wylie/Rev Mgmt 2026/`) ahead of the revenue call.

## Sources mapped so far

### 1. CoStar / STR — Weekly STAR Report
- **Access:** manual login + manual download. No scheduled email delivery available.
- **Format:** standard STR "Weekly STAR Report" `.xlsx`. Same STR ID, same sheet
  layout every week (`Glance`, `Segmentation Glance`, plus supporting tabs).
- **Data:** Occupancy / ADR / RevPAR and Index (MPI/ARI/RGI) vs. comp set, by day,
  plus segmentation by Transient / Group / Contract.
- **Automation potential:** High. Structure is fixed, so a parser can pull the
  numbers straight out — Kate still has to download the file, but no more manual
  reading.

### 2. Lighthouse (rate shop)
- **Access:** login required. This is the exact source of the rate-grid screenshots
  in the current Word doc (Rates → Table view → Brand.com/Public filter).
- **Format:** `.xlsx` export available on demand (Next 90/365 days, selected month,
  custom range) — `Overview`, `Rates`, `vs. Yesterday`, `vs. 3 days ago`,
  `vs. 7 days ago` tabs, clean and structured.
- **Built-in scheduling:** Lighthouse has a native **Schedule → Periodic report**
  option — weekly email, same data, no login required once turned on.
- **Automation potential:** Highest of all five sources. **Open decision:** turn
  this on? If yes, Janice can catch the weekly email and this source needs zero
  manual steps.

### 3. Expedia Partner Central
Four sub-areas Kate checks, three different logins/products:
- **Revenue management / Rate insights** (`apps.expediapartnercentral.com`):
  "Fair Share" revenue estimate (booked revenue vs. Expedia's modeled fair share),
  average lowest rate vs. competitive set, upcoming demand events, and a rate
  comparison table with a *different* comp set than Lighthouse (adds The Cabot
  Lodge, The Salem Inn). Has a Download button on the rate comparison table.
- **Data and insights hub:** Revenue, conversion rate, page views, room nights,
  ADR — trended vs. last year, with an AI "Generate insights" summary.
- **Promotions Hub:** active promotion performance (net revenue, bookings, room
  nights per promo). Has Share → Download.
- **TravelAds** (`travelads.expedia.com` — separate login realm): sponsored
  listing spend vs. room nights clicked, plus a Reports section for spreadsheet
  export (bid/budget history).
- **Automation potential:** Split. Rate insights and Promotions both have real
  Download buttons — not yet built, same pattern as CoStar once picked up. The
  two screens Kate actually checks weekly (Data & Insights hub, TravelAds
  Performance dashboard) are **confirmed no-export** — card/dashboard layouts,
  not tables, so even the Booking.com print-to-PDF trick won't produce a clean
  parseable file. **Decision made:** not worth building scraping/OCR for ~20
  numbers total across two screens — the report has a manual-entry table for
  these instead (see Build status below).

### 4. Booking.com — Sales statistics
- **Access:** login required (session tokens are one-time, don't carry over from
  a stale link — Kate has to be freshly logged in).
- **Page used:** Analytics → Sales statistics (`statistics/sales_insights.html`).
  Shows Kate's own Booking.com production: room nights and ADR trended monthly,
  vs. last year, plus a breakdown by room type and rate plan (BAR vs. advance
  purchase) with room nights / revenue / ADR per plan.
- **No file export found** — only a "Print this page" option, no download/.xlsx
  like STR/Lighthouse. This is Kate's own channel production data, not a
  rate-shop comparison (Booking.com also has Comparable properties / Ranking
  dashboard / Performance dashboard under the same Analytics menu, not
  confirmed as used weekly).
- **Solved:** Print → Save as PDF (native browser dialog — Kate does this
  click herself, Claude can't drive the OS print dialog) produces a page that
  looks garbled as plain text (bold rows render as doubled characters, e.g.
  "RRoooomm") but parses cleanly once read from the PDF's character
  positions instead of its text layer. **Built and working** — see Build
  status below.

### 5. Synxis (AVEN Hospitality CRS)
- **Access:** login required (saved credentials autofill, Kate confirms sign-in
  herself — Claude never submits a login).
- **What it's for:** this is the piece none of the other four sources have —
  Kate's own live on-the-books availability. Cross-referencing this against
  the comp set rates from Lighthouse **is the actual revenue management
  judgment call** the weekly routine exists to support — the other four
  sources are inputs to it.
- **Two report paths, easy to confuse:**
  - Reports → **Inventory** (no suffix): only supports **Subscribe**
    (schedules a one-time or recurring emailed report, rendered as XML) — no
    instant download.
  - Reports → **Inventory (Download)**: the one to use. Generates an
    on-demand `.zip`/`.csv` async job, tracked under its own "View Reports"
    queue, and also emails a completion notice to whatever address is in
    "Notification Information" (defaulted to Kate's).
- **Format:** CSV, one row per room type per date — `Cal_Dt`, `Avail_Qty`,
  `Sell_Qty`, plus group/channel detail. Summed across room types it matches
  the Express View "avail/sold" figures exactly (verified).
- **UI quirk to know about:** the "View Reports" table's Start Date/End Date
  columns are misleading — they don't reflect the actual date range requested.
  The real range is in the CSV's own footer (`Report Criteria` block, `start_dt`/
  `end_dt`). Don't trust the table; trust the file.
- **Automation potential:** High, same pattern as CoStar — manual login +
  generate + download, then fully parsed. **Built and working.**
- **Still worth checking later:** Lighthouse's "Add your On The Books data —
  it's free" banner (My OTB column currently shows `--`) suggests a native
  Synxis→Lighthouse integration might replace this whole join automatically —
  parked pending Lighthouse admin access (see OTB section below).

## Build status (v1 — done)

Script: [wylie_weekly_revenue_report.py](../live/wylie_weekly_revenue_report.py)

**Usage:**
```
python3 wylie_weekly_revenue_report.py \
  --str <STR Weekly STAR .xlsx> \
  --lighthouse <Lighthouse rate export .xlsx> \
  --booking-pdf <Booking.com Sales statistics print-to-PDF> \
  --synxis-csv <Synxis Inventory (Download) report .csv> \
  --out <output .docx>
```
`--booking-pdf` and `--synxis-csv` are both optional — omit either and that
piece is skipped (Lighthouse table loses its Avail/Sold column; Booking.com
section is left out entirely).

**What it produces**, all built from this week's real downloads:
1. Market Performance vs. Comp Set (CoStar/STR) — Occupancy/ADR/RevPAR by
   day, Index vs. comp set, segmentation by Transient/Group/Contract, with a
   flag line for any metric where Wylie fell below the comp set.
2. Rate Shop vs. Comp Set (Lighthouse) — full rate table vs. all six comp
   hotels, **with Wylie's Synxis Avail/Sold joined in as its own column**,
   plus two flags: days priced below the entire comp set, and days Wylie
   sold out while the comp set still had rooms open (the actual signal the
   call runs on).
3. Booking.com — Your Production — monthly room nights/revenue/ADR vs. last
   year, room/rate-plan breakdown, flagged when a month is behind last year.
4. Expedia — Manual Entry — blank tables for the Data & Insights and
   TravelAds numbers (no export exists for these two screens).
5. "For the call" — short note pointing at the Avail/Sold flags above.

Output lands in `my-work (outputs)/clients/wylie-inn/02 - Deliverables/`.

**Default weekly process (confirmed with Kate 2026.09.02):**
1. Kate exports Lighthouse (.xlsx, "Next 90 days" covers enough range) and
   Synxis (Reports → Inventory (Download) → Generate Report → View Reports →
   Download — not the plain "Inventory" report, which only emails a
   subscription).
2. Run the script with just `--lighthouse` and `--synxis-csv` (`--str` and
   `--out` are still required flags; STR can be skipped later if Kate decides
   she doesn't need that section, but the flag itself isn't optional yet —
   worth revisiting).
3. That's the report for the call — Wylie's Avail/Sold joined into the
   Lighthouse rate table, with the "sold out while comp set still has
   availability" flag.

**Fuller build (available, not default):** STR, Booking.com (production +
promotions), Expedia (promotions + screenshots) can all still be added the
same way they were built this session — see the source sections above and
the `--help` output on the script — for any week Kate wants the complete
picture instead of just the rate/availability check.
